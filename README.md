# 卫戍协议 · 战术终端

一个纯静态 Web 的《明日方舟》卫戍协议阵容推荐工具。先选**开局策略 + 核心/附加盟约**，系统按策略契合度和盟约给出阵容；也可以在“自己配阵容”里手动拼一套并保存。**过渡思路会随开局策略变化**。

**在线使用**：<https://1185077169.github.io/stronghold-advisor/>  
**GitHub 仓库**：<https://github.com/1185077169/stronghold-advisor>

## 怎么运行

**方式 A：直接双击 `index.html`**

数据已内嵌在 `js/data.js`，不依赖 `fetch`，`file://` 下也能跑。

**方式 B：本地 HTTP 服务（推荐）**

```powershell
cd D:\卫戍协议助手
py -3 -m http.server 8765
```

浏览器打开 <http://127.0.0.1:8765/>。

**方式 C：双击 `启动.bat`**

自动打开浏览器并启动本地服务；关闭命令行窗口即停止。

## 功能

1. **开局策略**：61 条策略按“核心盟约专属 / 通用”分组；选中后显示发起者、初始生命、完整效果，并给出“偏向【某核心】”提示。
2. **策略 + 盟约推荐**：顶部选核心盟约（可选附加盟约）；推荐按策略契合度、完成度、强度、可达性、装备、盟约激活综合排序。
3. **推荐阵容**：3 张卡，展示核心/外援上场数、还缺人数、可达性、强度、装备、**策略契合**、下一步操作；主播阵容带“主播”标记和可展开的**装备/转职**表。
4. **自己配阵容（v0.7）**：选核心/附加盟约和策略后，候选池常驻，可按“核心/外援/盾位/奶位/输出/等阶”筛选；支持「自动补核心」「自动补外援」「一键套用推荐」；9 个槽位可视化，点 × 直接移除，点空位聚焦搜索；实时计算核心 3/6、附加 2、盾奶输出、队伍强度、策略契合和结构警告；支持保存/载入/删除。下方提供**前中后期思路**和**逐干员装备/转职**输入框，由用户自己写；「填入参考」会按当前策略/阵容生成参考，但只填空位，不会覆盖已经写的内容。
5. **从推荐复制**：每张推荐卡和阵容库都有“复制到自定义”，可以把系统阵容作为起点再改。
6. **全部阵容**：37 套，按核心/附加盟约筛选，展开看核心 6 人、外援、**逐干员装备/转职**、**开局策略**、**随策略变化的前中后期过渡**、盟约效果、运营备注、来源。
7. **只看主播推荐**：筛选区一键只看 7 套主播/社区实战阵容；每套都带来源链接。
8. **大丑别名**：数据本名是“暴躁铁皮”，前端统一显示为“大丑”；干员列表、搜索、Ban、自配、商店查询都能用“大丑”找到。
9. **Ban 位 / Box**：ban 核心盟约、附加盟约、干员；box 模式按你勾选的可用干员算可达性。
10. **商店期望**：右侧“查看本数”选择 1-6 本，查看目标干员每次刷新的出现期望（近似模型，仅用于相对比较）。
11. **经济提示**：资金不跨回合、升级费每回合 -1、5-6 本再深刷等通用提示（不再需要手动输入资金/升级费）。
12. **本地记忆**：box / ban / 筛选 / 策略 / 自定义阵容保存在 `localStorage`；“重置本局”清空。
13. **分享链接（v0.7 新增）**：自配页「复制分享链接」把核心/附加/策略/干员，以及**用户写的思路和装备**一起编码进 URL 的 `#c=`；对方打开会自动跳到“自己配阵容”并载入，不需要服务器。已保存的阵容也能单独分享。

## 推荐评分 v3

```
score = 100 × (
  0.34 × 完成度        // 核心上场占比 75% + 外援上场占比 25%
+ 0.22 × 数据强度      // 干员面板/叠层效率归一化
+ 0.18 × 可达性        // 缺卡在当前本数下的可获取程度
+ 0.08 × 装备匹配      // 已选装备与推荐装备的重合度
+ 0.10 × 盟约激活      // 核心 3/6 人与附加 2 人的达成度
+ 0.08 × 策略契合      // 与所选开局策略的匹配度
- 抢卡惩罚            // 队友同核心/同外援
- ban 惩罚            // 核心干员被 ban
)
```

**策略契合**的判定：
- 策略描述里的核心盟约 vs 阵容核心：匹配 +0.45，不匹配 −0.15；
- 描述里出现阵容附加盟约：+0.10；
- 策略标签与阵容轴匹配：经济（远见/奇迹/投资人/助力）、精锐（高难度/T6 key）、部署（卡西米尔/叙拉古/突袭/不屈）、防御（坚守/不屈/协防）、输出（精准/奥术/灵巧/迅捷）、召唤（莱塔尼亚/谢拉格）各加 0.06–0.12。

自己配阵容用同一套思路：完成度按“已选人数 / 部署上限”，强度按“队伍总战力 /（单卡最高战力 × 部署上限）”归一化，策略不匹配会在警告里提示。

## 公开部署（v0.7 新增）

项目是纯静态站点，不需要后端。生成部署目录：

```powershell
py -3 -I tools/build_data.py     # 赛季数据有更新时
py -3 -I tools/package_site.py   # 生成 dist/
```

`dist/` 只包含 `index.html`、`css/`、`js/`、`favicon.svg`、`NOTICE.md`、`_headers`、`robots.txt`，可直接拖到 Cloudflare Pages，或推到 GitHub 用自带的 Actions 发布到 GitHub Pages。

完整步骤（Cloudflare Pages、GitHub Pages、EdgeOne Pages、阿里云 OSS+CDN、域名/备案、更新流程、分享与统计、合规检查）见 **[`部署指南.md`](部署指南.md)**。

## 已知限制

1. **阵容分两类**：30 套自动生成（按核心 + 外援强度/叠层排序）+ 7 套主播/社区实战阵容；自动阵容尚未用梯度榜人工校正，抖音阵容按视频画面整理、未逐局复现。
2. **主播装备表混有“通用”件**：未标“通用”的来自攻略原话，标“通用”的是按职业/机制补的推荐；转职槽位取舍以游戏内为准（规则是「变形同构体 + 对应盟约道具」）。
3. **策略标签是关键词判断**：策略描述里的“资金/刷新/精锐/部署/攻击/装备”等词决定标签，个别策略可能归类不准，可手工调 `js/engine.js` 的 `strategyTags()`。
4. **过渡思路 = 策略标签句 + 阵容干员节奏**：例如经济策略会提示“靠刷新/资金白嫖核心”，部署策略会提示“多再部署触发”，再拼上该阵容的具体人名；属于通用节奏，不是主播级细节。
5. **别名目前只映射了“大丑”→“暴躁铁皮”**：其他常用别名可在 `tools/build_data.py` 的 `ALIASES` 里补。
6. **商店概率是近似模型**：官方未公开精确权重，`js/data.js` 里的 `shopWeights` 是估计值，只适合比较不同本数/目标的相对难度。
7. **自配只做结构检查**：自动补核心/外援按“强度 + 盾奶覆盖 + 核心/外援匹配”排序，未考虑技能、模组和站位；思路和装备默认由用户自己写，「填入参考」给的是“策略标签句 + 当前阵容节奏”和按职业的通用件 + 非核心干员转职方案，仅供参考，不判断装备冲突和站位。
8. **没有干员图标**：当前用等阶色块 + 文字；图标可按需从上游 `icons/` 下载。
9. **干员数 217 > 本赛季 143**：数据可能混有往期/变体；如发现某干员不在本局可选名单，可在 box 中取消勾选。
10. **赛季切换**：新赛季需要重新拉取上游数据并跑 `build_data.py`；阵容库会自动重算。公开部署时记得再跑 `package_site.py` 并重新发布 `dist/`。
11. **分享链接不是云存档**：阵容编码在 URL 里，链接较长；对方打开后只载入自配阵容，不会同步 box/ban/已保存列表。清理浏览器本地数据后，已保存阵容仍会丢失，重要阵容建议同时存分享链接。
